Research update · 24 August 2026 · Evo2-1B vs GenomeOcean-4B

Class-Specific BGC Generation

A class-specific LoRA puts class-appropriate biosynthetic machinery into de novo DNA on three independent compound classes — against controls that produce exactly none. Changing the model raises that rate 9.8×; seeding the old model erases the gap and reverses it.

Phase 3

One class at a time

The pivot was to stop conditioning on a class label and instead route to a per-class adapter. Phase 1 had measured the class tag at −0.0006 nats — no effect — so the label was never the lever. Target: RIPP, trained on the biosynthetic core only.

Two constraints shaped everything after. We train on the strict core — a median 2,191 nt of a ~21,900 nt region — so generations contain no transport, regulatory or resistance genes by construction. And the 1B's 8,192-token context is a hard model limit, not a config choice.

Correction

What the audit found

Assembling a full report surfaced four defects. Each was caught by measurement, and each is recorded in place rather than edited away.

Retracted — fan-out shard collision Five Phase-4/5 arms at n = 188, WIDE refuted at Holm p = 4.1e-04 and 3.2e-05 Four workers launched with the same --seed wrote byte-identical shards. Effective n was 47–141. Rates survived (duplication was uniform); one of two p-values did not — the 8 kb contrast fell to p = 0.15, n.s. All Phase-3 sets audited clean.
Retracted — extraction truncated on a stop byte Sequences end early; the model has learned to stop The extractor kept only the leading ACGTN run, discarding a median 6.2 kb of 99.9%-valid DNA. It hit adapters ~35× harder than base models, so it loaded onto the treatment arm: 45.5% vs 2.0% below the scoring window.
Corrected — marker-set artifact PKS reaches ≥2 class domains in 74% of real cores vs RIPP's 20% OBLIGATE_DOMAINS[PKS] holds several Pfam models per catalytic domain, so a single T3PKS gene scores 2 unaided. Collapsed to catalytic units it is 0.300; by distinct gene, 0.060 — level with RIPP.
Retracted — the early-stopping speedup ~75% of PKS generation compute runs after the model has finished Measured on the wrong quantity. The median ~1,750 nt stop was the first stop of any kind — overwhelmingly degeneracy, not EOS. With real token ids only 9/24 rows emit EOS at all, so an all-rows exit delivered 1.01×. Batched decoding is bounded by its slowest row. Per-row exit is worth 38.5%; the win from that build was constrained decoding instead.
The finding that replaced the marker artifact is more useful. No class has multi-gene cluster structure in the strict-core span — all three sit at 0.06–0.08. That is a property of strict-core trimming, not of any class, so changing class cannot fix it. Only span width or context can.

Finding

Rarely the harder member

Given a class, the model overwhelmingly produces its simplest member. This read "never" until 24 August, when the one contrast we powered up turned a zero into a small non-zero — the correction is below the table.

Retracted — "never" was a small-sample artifact TERPENE: the model produces the precursor and never the cyclase — 0/13 Pooling Evo2 de novo to n = 800 (+600 records, 600/600 unique, no overlap with the original arm) raised detections from 13 to 48 and produced 3 cyclase calls = 0.062. The limitation is real — 0.062 against a real-core 0.440, p = 1.65e-05 — but it is rarely, not never. Two of the three zeros above have not had this treatment, so they are quoted as untested.

The harder member is, in every case, the longer one — T1PKS at a median 7,665 nt against T3PKS at 1,083. The 1B's training budget is 7,992 nt, so half of all T1PKS records do not fit. The PKS adapter is 59.3% T3PKS by construction, and it reproduced its substrate exactly.

And the limitation survived the model swap. GenomeOcean makes the cyclase at 20/126 = 0.159 against Evo2's 0.062 — higher, but not significantly (p = 0.132), and both sit far under real cores at 0.440. A 6.4× context and 4× the parameters did not lift the harder member. That makes the ceiling look like a property of the substrate — one context limit, one trimming rule — rather than of either model.
Diagnosis

The model was stopping all along

Generations ended early while hit_eos read 0 in every arm ever produced. The cause: token ids 0 (EOS), 1 (PAD) and 32 (space) all decode to the same character, and the whole pipeline read the decoded string.

We never trained token 0. --eos-token appended a five-byte string, |END|, which never once fired. The real EOS came from Evo2's pretraining and our fine-tuning sharpened it 51×. It is now appended unconditionally, with no flag.

This retired a claim that had propagated for a month. The model-comparison doc listed "Evo2 has no usable EOS" as one of three reasons to switch models. Evo2's EOS is real; what GenomeOcean actually offers on this axis is convenience — its tokenizer auto-wraps BOS=1 … EOS=2 and its runtime honours it. The trainable class token remains the genuine structural difference.

Degeneracy is a separate failure. Two mechanisms were tested and both rejected: the pre-collapse context is not worse on-class (p = 0.22), and degenerate records show no more within-alphabet repetition than clean ones. It is an abrupt exit from the nucleotide manifold — encouraging for constrained decoding, since there is no repetition loop to fall into, but whether constraining yields usable sequence there is untested.

Phase 8

Seeding erases the model gap — and reverses it

Every finding above was confounded with Evo2-1B. GenomeOcean-4B is the control that separates "the method" from "this model", re-running Phase 7's exact endpoint on a different architecture, tokenizer, context and pretraining corpus. Running the full 2×2 — both models × seeded and de novo — is what kept the answer from inverting.

"GenomeOcean is 9.8× better" is really "GenomeOcean de novo ≈ Evo2 seeded." The model gap is conditioning-dependent, not absolute. GenomeOcean's real advantage is that it reaches seeded-level performance without needing a seed — not that it is a better generator in general. Comparing seeded GenomeOcean against de novo Evo2 would have inverted the conclusion, which is exactly what building the two missing cells was for.

Two denominator traps, both declared. 61/200 GenomeOcean seeded generations are empty — its EOS fires immediately after the 8-nt seed. The battery scored the 139 non-empty and reported 0.576; an empty generation is a miss, so the arm rate is 80/200 = 0.400. And the seeded row is not length-matched: Evo2 writes ~2,500 nt and fills the window, GenomeOcean's seeded continuation has a median of 893 nt. That disadvantages GenomeOcean — the mirror of the de novo row, where its working EOS stops it at 1,009 nt and only 43/200 filled the window.
Corrected — what loss parity predicted All three models encode class equally, so a model swap alone may not move the endpoint It moved it 9.8× de novo. Equal class probes (0.878–0.91) and equal fine-tuned loss (1.2414 vs 1.2143 bits/nt) did not predict equal generation. Representation parity says nothing about how well a model can be made to write from that representation — which is the real content of "the bottleneck is generation, not representation".

⚠️ At 4.25 B against 1.1 B this arm is not parameter-matched, and context, tokenizer and pretraining corpus all differ at once. A win says "this model does better"; it does not isolate which axis did it. TERPENE was chosen so that context at least is excluded — 94% of it already fits Evo2, and the 6.4× context bought only +5.3% more training records.

X1 · alongside

Generation correctness and speed

One missing capability — seeing the sampled token ids — blocked all of these. vortex returns logits and strings but never ids, and ids 0, 1 and 32 all decode to the same character, so the pipeline could not tell a stop from a collapse. That capability now exists; what remains is wiring it into the generation scripts.

  • X1gToken-id-aware generationBuilt. The sampler is wrapped to mask logits, record ids and exit early — nothing depends on vortex's return value.
  • X1aConstrained decodingWorks, and was the real win from that build: junk ids 247 → 0 at 1.01× cost. Mask every id outside {A,C,G,T,N,EOS} to −∞.
  • X1bTrain the real EOSShipped, and with no flag — id 0 is appended unconditionally. The 5-byte |END| string is retired.
  • X1ehit_eos tests the token idStill open in generate_bgc.py, which reads the retired string and so reports a structural zero. Until it lands, no hit_eos from that path may be quoted as evidence about termination.
  • X1fPer-row early stoppingThe simple version does not work — see the retraction above. Per-row exit is measured at 38.5% of decode compute (157,490 tokens needed vs 256,000 paid) and needs vortex's cached inference_params rebuilt for surviving rows. Cheaper first: shorter requests and smaller batches.
  • X1iSnip-and-replaceDetect a degenerate or zero-length record, discard, regenerate the slot. Rejection sampling; legitimate as selection provided the discard rate is reported.
  • X1dDegeneracy needs its own gateConstraining does not fix it — at a uniform-distribution position masking just forces an arbitrary base.
X2 · released

Subclass interventions

These were held pending GenomeOcean, in case it reattributed the finding from the method to the context limit. It did not — the harder-member ceiling holds in both models — so the hold is lifted and X2b is the next real experiment.

  • X2aBigger denominatorsNot a blocker — all three contrasts are already significant. Turns a direction into a rate.
  • X2bSeeded hard-subclass controlSeed from a real T1PKS or cyclase exemplar. If seeded generation still yields zero, the limitation is real. The most informative cheap experiment on the board.
  • X2cInverse-frequency weightingDo not run before X2b — 31% of PKS training carries a ketosynthase and produced 0% of output, far worse than frequency alone predicts.
  • X2dSubclass-conditioned adaptersA T1PKS-only adapter, ~1,200 records — the honest route to any modular-PKS claim.
